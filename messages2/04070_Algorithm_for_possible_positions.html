Algorithm for possible positions

From: whuang@ugcs.caltech.edu (Wei-Hwa Huang)
Date: 08 03 1999 00:00:00 GMT

The most desirable algorithm in Chess computing has the following
requirements:

Given any legal position in chess, generate the best move.

The "best move" has several definitions, of course, but in its
weakest form we might define it to be: if there is a winning strategy,
then the best move is one that is part of a winning strategy; else, any
move is the "best move".

We might call this "God's algorithm" (GA). I note the following
properties of GA:
- If we could chart out the entire move tree of chess,
we would have GA.
- Existing algorithms can do a reasonable job of approximating GA
via certain "obvious" heuristics (e.g., don't leave attacked pieces
undefended) that can be refined to get even closer to GA (e.g.,
it's okay to leave attacked pieces undefended if you can guarantee a
checkmate in three moves).
- For certain positions, GA is easy to computer (e.g., mates in 3).
- No one has (provably) implemented GA yet.

Recently, I have in mind another algorithm, with the following condition:

Given any position in chess, determine if the position is a legal
position.

A "position" here includes state information on what is on each of the 64
squares, which side is to move, whether or not each side can castle in
the future, whether or not en passant captures are possible and where they
are, and some sort of progress record of how close the game is to a
50-move draw or a repetition draw. (Or, to simplify matters, we may consider
a simpler version of chess where there is no draw by repetition or 50-move
law.) A "legal position" means a position which could potentially
occur in an actual game.

Let's call this one "Hero's Algorithm," named after Herodotus, the historian
who chronicled many wars and stories and apparently made some up too.

Hero's algorithm (HA) has properties that has many similarities to God's
Algorithm:
- If we could chart out the entire move tree of chess,
we would have HA.
- Existing algorithms can do a reasonable job of approximating HA
via certain "obvious" heuristics (e.g., if a player is in check and
he has made the last move, then the position is illegal) that can be
refined to get even closer to HA (e.g., if both players are in check,
the position is illegal).
- For certain positions, HA is easy to compute.

In a sense, HA is the opposite of GA: in GA, you are trying to find a
path down the move tree that leads to a winning position; in HA, you are
trying to find a path up the move tree that leads to the starting position.

Now, the questions:
1. Has any progress been made on HA? Has HA ever been stated before?
2. Is HA simpler, more complex, or about as difficult to solve as GA?
3. If we made progress on computational methods for HA, would that
help us approximate GA better? Or would it be no help at all?
How about vice versa?
