: I don't think it's that it's easy to program -- it's certainly not as easy
: to program as Connect-4 or checkers.

I don't know about Connect-4, but I am not sure I would say that Checkers
is easier than Othello. Othello has a set number of moves (can't be more
than 30 for each player, 32 if you use the earlier rules for playing the
first four pieces, which I think is what seperates reversi from Othello).

There are several rather effective evaluation functions that can be
defined with several dozen lines of code. Hell you can get an ok program
using positional play which simply requires you to define values for
different parts of the board.

I developed a version in under a thousand lines of code, and mind you it
had several different approaches implemented as different players. Most
of the effort was spent defining the board and the referee (which handeled
scoring and flipping pieces).

Checkers on the other hand is theoretically an open-ended game, and
despite its smaller board (32 as opposed to 64 squares) has nuances that I
believe make it a little harder to program a good checkers playing
program.

: Perhaps it's because there are a lot of easy-to-define metrics for
: different strategies (e.g. maximize the number of your tokens, maximize the
: number of your possible moves, minimize the number of your possible moves,
: maximize the number of your "locked" tokens, etc.) so that you can easily
: write different strategies to play against each other. I agree that these
: strategies are fairly-easily beaten by a talented player (or at least they
: were when I was writing these programs, when a 6-ply search took too long
: -- perhaps the current machines could handle a 10 or 12-ply search) but as
: a learning tool for programming they're useful.

Actually from what I understand the strongest programs use mobility
(maximize your moves as you get closer to the end while minimizing your
opponents) as the basis of their algorithms. Further I would say that
using an Alpha-beta search with good optimized C or C++ code could easily
handle 10 to 12 ply. My version used 6 ply and was written in Java 1.0
and ran at acceptable speed on a 33mhz Workstation even before using more
advanced Java features such as Just in time compile.
