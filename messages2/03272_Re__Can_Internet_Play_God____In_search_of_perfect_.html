I think you can reasonably argue that chess is not perfect: the rules
have many special cases and a complex set of rules are required for
termination of the game. Furthermore, draws are fairly common.

I think Go is much closer to "perfection": The rules are simple, few
special cases needs to be considered (the ko rule basically says that
no situation can be repeated), termination is (in the chinese)
determined by a simple rule (three consecutive passes). The japanese
variant has some complexity about detecting the end because passing
doesn't cost a stone. Hence, playing out the endgame can change the
score, which it doesn't in the chinese variant. (There may be some
slight errors in this description it has been ages since I last played
Go).

If we consider only two-player non-random games, I think the following
criteria must be met before we can even consider perfection:

1) The rules must be simple, with few (if any) special cases.

2) Termination of the game must be ensured by simple rules, or better
yet, through no extra rules.

3) The chance of winning must be equal for both players, with no
simple strategy ensuring victory/draw for any particular player.

4) Exhaustive search by computer must be intractable.

5) The game must be playable in reasonable time.

Point 3 is _very_ hard to judge, as in a deterministic game perfect
game play must exist. Just about the only way I can see of judging
winning chances is by letting experienced players play each other in a
large number of games and count the number of victories/draws/losses
for the first player.

Point 5 may seem like an extension to point 2, but in point 5 I
consider the average playing time where point 2 considers the
worst-case playing time. In chess, there is a large difference between
these. Withoutout some means of limiting the time for a move, every
game can theoretically last forever, so I just want it to be
_possible_ to finish an average game quickly.

Of the classical games, chess fails on point 1 and 2. Go may favour
the first player slightly (AFAIR), but is by far the most intractable
of the classical games. It may be sligtly on the long side. Othello
has problems with point 4, as a large part of the endgame is tractable
to do perfectly on a computer. Some statictics has been made on
tournament play giving 47% win for black (1st player), 3% draws and
50% wins for white. This would suggest a modification in the winning
criteria saying that a draw should be counted as a win for black.

For many of these points there exist classical "fixes": For
termination, a rule disallowing repeated states usually works, but may
require memory of a large number of previous states. Someone suggested
replacing the termination rule in Abalone with this.

An "equalizer" rule for point 3 has been suggested: the first player
makes a move. Then the second player decides if he wants to play
against this move or take over, letting the original first player play
the second move. The rest of the game is alternating as usual. This
assumes that there exist at least one opening move that leads to equal
chances, so is in essence no different than starting the game in
another position.

The playing-time problem can be "solved" by putting a time limit on
the moves, using chess-clocks or other means. But if the number of
moves required to finish a game is large, this doesn't help.

The tractability problem can not be solved by adding to the rules, nor
(obviously) does this work for the game complexity.

>If someone can define the 'perfect game' in such a way as to be a perfect
>game to everyone, I'll be thrilled, but somehow I doubt it's possible.

I agree. I'm sure a lot of people will disagree with some of the above
points. In a sense, some of the points are even contradictionary: a
small number of moves to finish a game tends to make it tractable by
computer search. Unless, that is, the number of possible moves at each
stage is very large.

Also, fulfilling all of the above points doesn't necessarily make a
game interesting. Consider the following game:

An NxN square grid is initially empty, and the players alternate
putting stones on the grid points. The last player to make a move has
lost. Now, this would be completely trivial without the last rule: You
can not play adjacent to the last played stone, and if you can't play
anywhere with this restriction, you pass and the next player moves.

I believe this game fulfills the criteria above: it has simple rules,
it terminates, no draws are possible, winning/losing is non-trival, it
is intractable (assuming a reasonably sized grid) and it can be played
fast. However, I doubt many people would find the game interesting,
except perhaps from an academic viewpoint. You may, of course, prove
me wrong by gathering a large fan crowd for this game. ;-)
