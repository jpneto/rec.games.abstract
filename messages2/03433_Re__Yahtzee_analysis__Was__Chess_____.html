Actually I've been sufficiently stimulated by this discussion to code up
a yahtzee tree builder.

My first naive attempt would have taken 324 years to run.

By improving on the rolling mechanism (pre-calculating the 252 rolls
for 4s, the 126 rolls for 3s etc. and their weights) I dropped it down
to
8 years.

Next I optimized the code a little to bring it down to 3 years.

Then I put in some pruning code (EG If you need only Yahtzee and sixes,
you never want to keep two different dice and roll the rest) to bring it
down to 1.6 years (I had hoped this would do much better)

Then I put in some code that recognized when scoring over 65 above the
line was impossible and so made the above line score irrelevant, leading
to a bit of state collapsing. I'm not sure how efficient that makes the
code, but my guess is it'll at least halve it (if all the above line
categories are filled, or filled with low scores, it reduces those
states by a factor of 32).

Finally I ran the code on a slightly faster computer to reduce it by a
factor of 3/4. So maybe 6-8 months?

Now the algorithm is extremely parallelizable, so on a massively
parallel machine each machine could be calculating for each roll of the
dice. With, say 128 processors, we could solve yahtzee in 3-4 days.

Now, (tracing the thread right back to its roots), we can't do *that*
with chess.
