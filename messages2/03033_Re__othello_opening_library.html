Hi,
I wrote an automated learning opening mechanism for eclipse, a program I
wrote
with Colin Springer which is the #2 comouter player in the world
(according to
ios). There is I think a problem with move sequence based opening
libraries: that is, there are LOTS of tranpositions which occur at various
stages of the game.
There are programs that fo it this way, but I believe they have fancy
mechanisms
to re-connect transpoing lines; IMO this is a pain in the arse.

Eclipse uses a position based book; it stores all positions as 4 32
bit numbers along with a score for the position (the position is rotated
and flipped
each of 8 ways to get the lowest valued symmetry, which resolves the f5 d3
c4 e6
symmetry problem and other transpositions). Then the book is minimaxed,
and
to chose a move from a given position we simply look for all it's children
in the book, and chose the highest valued one (if found). This method also
suffers from
tranpositions sometimes (but is easier to deal with than the move sequence
approach IMO); for example your opponent may play a new move, and
you may have only one (bad) move in the book... but a better move is
sitting there to be played. These cases can be fixed by making sure the
book eval
never drops; if so you've hit this situation, and should leave book
instead of playing that move.

This is a short and fast explanation of the eclipse book ... I can go into
more details if you like.
